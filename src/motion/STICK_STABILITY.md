# 카메라 채 추적 안정화

## 후속 조정: 빠른 연주와 시각 효과

- 현재 위치 필터는 정지 시 `beta .04`를 유지하고, 유효 이동 속도 .4~2 영상 높이/초에서 `beta .10`까지 점진적으로 높인다. 회전은 `1.2 / 1.6 / 2`, 최대 각속도는 20 rad/s다.
- 새 영상 프레임의 추론 최소 간격은 16ms, 표시 보간은 6ms다. 실제 카메라 FPS와 추론 시간보다 빠른 인식을 보장하지 않는다.
- 채 표시 유지 시간은 250ms이며 350ms에 사라진다. 타격용 stale 판정과 재인식 보간 중 타격 차단은 유지한다.
- 판정 반경 배율은 1.34, 최소 속도 .16, 타격 간격은 65ms다. 영역 내부에서도 반경 대비 .22 이상 물러난 후 .10 이상 돌아오면 되치기를 인식한다. 실제 깊이 방향 접촉을 측정하는 방식은 아니다.
- `PlayScene`은 별을 바닥으로 떨어뜨리고 타격에 맞춰 도약시킨다. RAF는 정지 시 중단되며 연속 타격의 에너지는 누적하지 않는다. 악기 변경은 240ms 확대/페이드로 표시한다.
- 자동 테스트 65개 통과: 10Hz 내부 되치기 10회, 정지 잡음 오타격 방지, 큰 원형 동작의 추적 및 위치 오차 검증을 추가했다. 실제 사람의 징/꽹과리 연주는 별도 웹캠 검증이 필요하다.

아래는 최초 안정화 작업의 분석과 당시 설정 기록이다. 후속 변경값은 위 내용 및 `stickInteractionConfig.js`를 기준으로 한다.

이 문서는 현재 `/experience`의 React + MediaPipe + SVG/canvas 경로를 설명한다. 이전 3D 장구/상체 추종 경로와 구분한다.

## 분석한 흐름과 원인

`CameraProvider`의 영상 → `useHandTracking`의 640px 이하 추론 입력 → MediaPipe 21개 랜드마크 → 손 연결 → 손잡이/회전 필터 → viewport 투영 → `CameraInstrumentStage`의 RAF canvas → 기존 `stickHitEngine` 순서다.

- 이미 One Euro가 있었지만 grip 설정은 `4 / 22 / 2`였고, 최대 지연 거리 제한이 필터 출력을 원본 쪽으로 되돌리고 필터 상태까지 덮어썼다. 오검출을 검사하기 전에 속도와 필터에 입력하고 있었다.
- 기존 필터는 이전 원본 대신 이전 필터 출력으로 미분했고, 실제 프레임 간격을 8.3~100ms로 제한했다. 중복·역순 timestamp도 거르지 않았다.
- 좌우 분류를 매 프레임 그대로 tracker 키로 사용했다. 분류가 바뀌면 다른 손 좌표가 같은 필터에 들어갈 수 있었다.
- 짧은 손실에도 이전 속도를 이용한 이동이 적용됐고, 재등장 시 별도 시각 보간이 없었다.
- 회전에는 unwrap·각속도 제한·One Euro가 있었지만 순간적인 방향 반전을 따로 검증하지 않았다.
- 미러링은 손 측정에서 한 번, cover crop은 화면 투영에서 한 번 적용되고 있었다. 중복 변환은 발견하지 않았으며 이 규칙을 유지했다.
- 채 좌표는 React 상태가 아니라 ref를 통해 RAF로 전달된다. 약 120ms 주기의 React 상태 갱신은 안내용이다. 이 구조를 유지하고 오래된 timestamp를 무시한다.
- `video.currentTime`만으로는 새 영상 프레임을 구분할 수 없었다. 가상 카메라 20 FPS에서 약 30 FPS의 중복 추론을 관찰했다. 실제 프레임 콜백 기반으로 변경 후 같은 환경에서 추론 약 20 FPS, 렌더 약 60 FPS를 확인했다. 지원하지 않는 브라우저만 기존 currentTime 비교로 동작한다.

## 적용 내용

1. X/Y에 독립 One Euro, 손마다 독립 상태를 사용한다. 입력 timestamp는 밀리초이며 필터 내부에서 실제 간격을 초로 변환한다. 미분은 이전 유효 원본에서 계산한다.
2. 입력은 영상 높이 1을 1000 단위로 환산한다. X에는 영상 종횡비를 적용한다. 따라서 beta 설정이 웹캠 해상도나 창 크기에 따라 달라지지 않는다. 별도 위치 필터와 원본 좌표 강제 보정은 사용하지 않는다.
3. 두 손의 위치·예측 이동·손바닥 폭·분류를 함께 고려해 최대 두 결과를 일대일 연결한다. 교차 근처에서는 불안정한 좌우 분류보다 이동 이력을 우선한다. 연결이 애매하면 잠시 유지한다. 장시간 잃은 손은 다른 분류의 손에 이어 붙이지 않는다.
4. 이동 거리만으로 차단하지 않는다. 시간 간격, 이전 속도, 새 속도, 가속도, 예측 오차, 손바닥 크기와 분류 불확실성을 함께 검사한다. 이상치는 필터/속도에 넣지 않는다. 연속 측정으로 새 위치가 확인되면 짧은 복구 보간을 거쳐 받아들인다.
5. 손실 시 마지막 보이는 위치·회전을 고정한다. 100ms까지 유지하고 350ms까지 흐려진 뒤 비활성화한다. 재등장 시 80ms 보간하며 이 기간은 stale로 처리한다. 장기 손실·손 정체성 변경·영상 종횡비 변경은 필터·속도·잡기 상태를 초기화한다.
6. 회전은 최단 각도차를 사용한다. 순간 반전은 다음 측정으로 확인하며 정상적인 연속 회전은 허용한다. 각도 필터와 최대 각속도 제한은 위치 필터와 독립이다.
7. 새 프레임이 있을 때만 최대 약 33회/초 추론한다. RAF는 최신 측정 사이를 최대 12ms 보간한다. 화면 보간 중간점을 새 타격 측정으로 취급하지 않는다. 타격 엔진에는 기존처럼 측정 timestamp와 필터링된 채 끝점을 전달한다. 손실·복구 중에는 stale로 기존 타격 차단 경로를 사용한다.

`stickHitEngine`, SVG 자산, 악기 배치, 채 길이, 카메라 연결·선택, 페이지 라우팅은 이번 안정화에서 변경하지 않았다. 디버그 쿼리는 악기 변경 시 유지한다.

## 설정

`src/config/stickInteractionConfig.js`에서 조절한다.

| 항목 | 값 | 단위/의미 |
| --- | --- | --- |
| grip minCutoff / beta / dCutoff | 1.2 / 0.04 / 2.0 | cutoff Hz, 고정 1000단위 좌표 |
| rotation minCutoff / beta / dCutoff | 1.2 / 0.8 / 1.0 | cutoff Hz, 각도 rad |
| lostTrackingGraceMs | 100 | 손실 중 완전 불투명 유지 |
| settleMs | 350 | 마지막 유효 측정 이후 비활성화 |
| reacquireBlendMs | 80 | 재등장 보간·타격 차단 |
| renderBlendMs | 12 | 일반 화면 보간 최대 시간 |
| staleAfterMs | 100 | 새 측정이 오지 않는 경우에도 타격 차단 |
| jumpMinDistance / jumpSpeed | 0.16 / 8 | 영상 높이 / 영상 높이·초⁻¹ |
| jumpAcceleration / jumpInnovation | 140 / 0.12 | 영상 높이·초⁻² / 영상 높이 |
| inferenceIntervalMs / inferenceMaxDimension | 30 / 640 | 추론 최소 간격 ms / 입력 최대 px |

요청 초기값 `dCutoff: 1.0`도 먼저 비교했다. 3Hz 왕복 합성 입력의 최대 위치 지연이 영상 높이의 약 0.0521이었다. 2.0으로 조정하면 약 0.0378로 감소해 빠른 방향 전환을 위해 2.0을 채택했다. minCutoff와 beta는 제안값을 유지했다.

## 검증 결과와 한계

자동 검증:

```powershell
node --test --test-isolation=none src/motion/*.test.js src/camera/*.test.js
npm run build -- --emptyOutDir=false
```

- 합성 정지 잡음의 X 표준편차: 원본 0.002458 → 필터 0.000866, 약 65% 감소. Y 이동 및 작은 회전 잡음을 함께 입력했다. 실측 손 떨림 감소율이 아니다.
- 느린 이동, 3Hz 빠른 왕복, 16~65ms 가변 간격, 고속 회전, 각도 경계, 단발 좌표 튐, 장기 손실, 손별 독립 상태, viewport 역투영을 검증했다.
- 손 교차 중 결과 배열 순서 변경과 좌우 분류의 단발/연속 뒤바뀜을 검증했다. 애매한 교차 순간은 양손 각 1프레임 유지했고 정체성 교환은 없었다.
- 추적 손실과 재등장 보간으로 가짜 타격이 발생하지 않는지 기존 타격 엔진과 함께 검증했다.
- Chrome 가상 카메라에서 모델 로딩, 개발 디버그, 악기 전환, 창 크기 변경, 카메라 종료, 런타임 오류 없음, 배포 빌드의 디버그 미표시를 확인했다. 이는 실제 손을 인식한 테스트가 아니다.

실제 웹캠의 정지 손, 빠른 타격, 가림·교차 정확도와 전체 지연은 이번 작업에서 측정하지 않았다. 두 손이 완전히 겹쳐 시각 정보가 없어지면 정체성을 보장할 수 없으며, 추정이 불명확한 동안 채를 유지/비활성화하는 쪽으로 처리한다. MediaPipe 자체 추론 시간은 여전히 메인 스레드 비용이다.

## 실제 장비 확인 방법

`npm run dev` 실행 후 `/experience?instrument=janggu&debug=tracking`을 연다. 배포 빌드에서는 쿼리가 있어도 디버그가 표시되지 않는다. 쿼리의 `debug=tracking`을 제거하면 꺼진다.

분홍 점은 원본 손잡이 좌표, 흰 점은 화면에 표시되는 손잡이다. 패널은 원본·필터 좌표, 이동 속도, 손실·이상치·손 구분 상태, 타격 가능 여부, 카메라/추론/렌더 FPS를 250ms 간격으로 표시한다. 좌표는 미러링된 영상 정규화 좌표이며 손 분류 점수는 손 검출 정확도 자체를 뜻하지 않는다.

1. 양손 주먹을 10초 가만히 유지: 흰 점과 채 끝의 잔떨림, raw/filter 차이를 확인한다.
2. 천천히 원을 그리고 좌우 이동: 끌림·계단 이동 없이 따라오는지 확인한다.
3. 빠르게 상하 타격 및 방향 반전: 채와 손의 지연, 이상치 오판정, 타격 누락을 확인한다.
4. 양손 교차와 겹침 후 분리: 채 색/역할이 바뀌지 않는지 확인한다. 완전히 겹칠 때 일시 유지가 가능하다.
5. 한 손을 약 100ms, 200ms, 1초씩 가린 뒤 복귀: 유지→흐려짐→비활성화, 재등장 보간, 손실/보간 중 타격 차단을 확인한다.
6. 16:9 창과 세로 창을 오가며 크기 변경: 손잡이와 채 끝의 상대 위치, 장구 위치, 좌표 뒤집힘 여부를 확인한다.

## 변경 파일

- `src/utils/oneEuroFilter.js`: 시간·미분·중복 측정 처리.
- `src/config/stickInteractionConfig.js`: 필터·손실·이상치·연결 설정.
- `src/motion/handMeasurement.js`, `handAssociation.js`: 유효 좌표 측정과 손 정체성 연결.
- `src/motion/stickTracker.js`: 이상치, 위치·회전 필터, 위치 유지, 재등장/렌더 보간.
- `src/hooks/useHandTracking.js`: 새 영상 프레임 기준 추론, 연결 적용, 진단 수치와 자원 정리.
- `src/components/sticks/CameraInstrumentStage.jsx`: 렌더 보간과 측정 기반 타격 분리, 디버그 점/FPS.
- `src/components/sticks/TrackingDebug.jsx`, `src/pages/InstrumentPlayPage.jsx`: 개발 전용 디버그 연결.
- `src/motion/stickStability.test.js`, `stickInteraction.test.js`: 새 안정화 검증과 기존 유예/유지 조건 갱신.
